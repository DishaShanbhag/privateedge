## Freeze

- Date: _not yet frozen_. Planned 2026-11-20; moved, because the test set is still being labelled. The team sets the date once every test label is checked (proposed 28 Nov, test run 29 Nov, report 3 Dec).
- Test-set SHA-256: _see `data/test/TESTSET_SHA256`_ (`eval/hash_testset.py`)
- Git tag: `freeze-<date>` on the commit that records the hash

What is frozen at the tag, and may not change after it (any later change is reported as post-freeze):
- Prompts: `prompts/calendar_v0.txt` (v1 was tested and rejected, 2026-11-27), `prompts/notes_v0.txt`. Grammars: `schemas/calendar.gbnf`, `schemas/notes.gbnf`.
- Configs: `configs/*.yaml`, including verifier policies (`span_policy`, `value_source`, `notes_grounding`) and thresholds (`notes_retrieval_threshold`, B0's notes threshold).
- Code that decides outputs: `harness/resolver.py` (also B0), `harness/verify_calendar.py`, `harness/verify_notes.py`, `harness/b0_*.py`, `harness/retrieval.py`, and the Swift ports (`ios/CalendarCore`, `ios/PrivateEdgeCore`).
- Scoring: `eval/score_calendar.py`, the notes rubric, `eval/bootstrap_gap.py`.
- Model files: the pinned GGUF SHA-256s (`configs/_base.yaml`, `configs/C2.yaml`); llama.cpp b12387; Gemini `gemini-3.8-flash`, thinking level low.

Test-set rules: the people who tune prompts, verifiers or thresholds do not see test items or labels before the freeze. Each configuration runs on the test set once; results are reported whatever they are. Slices reported separately as well as in totals: `out_of_scope`, `unstated_rule`, `dev_duplicate`, real vs synthetic items.
